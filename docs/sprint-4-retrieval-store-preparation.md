# Retrieval Runtime Store Preparation\n\n## Purpose\n\nSprint 4 retrieval evaluation consumes the persisted EmbeddingStore produced by S3.2 and S3.3. The embedding matrix and JSON metadata are generated runtime artifacts and are intentionally excluded from Git.\n\nThis preparation step makes the runtime dependency reproducible without committing model checkpoints or generated embeddings to the repository.\n\n## Command\n\nFrom the repository root:\n\n    python scripts/prepare_retrieval_store.py --dataset-root "E:\\Privat File\\Projects\\Zargar Interview\\dataset\\jewelry-design-dataset"\n\nThe default split is test.\n\n## Behavior\n\nThe script:\n\n1. validates the local dataset root, split manifest, and selected best checkpoint;\n2. reuses existing S3.2 embedding artifacts when both required files are present;\n3. regenerates S3.2 embeddings when either required file is missing;\n4. reuses the S3.3 store when all three store files are present;\n5. rebuilds the S3.3 store when any store file is missing;\n6. verifies that the complete store exists before exiting successfully.\n\nUse --force when the embeddings must be regenerated from the selected checkpoint.\n\n## Runtime Artifact Policy\n\nThe following remain local runtime artifacts:\n\n- embeddings/*.npy\n- embeddings/*_generation.json\n- embeddings/stores/**\n- model checkpoints under results/ or checkpoints/\n\nThey are not committed to Git because they are machine/runtime state and can contain environment-specific paths or large binary data.\n\nA fresh clone or a newly checked-out branch therefore requires this preparation step before running retrieval evaluation.\n\n## Scope\n\nThis script does not:\n\n- retrain the model;\n- change the model architecture;\n- change S3.2 embedding generation;\n- change S3.3 storage format;\n- change retrieval ranking;\n- calculate evaluation metrics.\n\nIt only orchestrates the existing S3.2 and S3.3 runtime-generation steps.
